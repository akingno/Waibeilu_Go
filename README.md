# 外北陆热线

当前服务入口为 `server.mjs`，使用 Node.js 和 SQLite。

## 运行

使用支持 `node:sqlite` 的 Node.js 22.13+（建议 Node.js 24 LTS），安装依赖后启动：

```sh
npm ci --ignore-scripts
npm start
```

默认监听 `127.0.0.1:8080`，可通过 `PORT` 修改端口。
Windows 也可以在安装依赖后运行 `start-local.ps1`。

## 聊天图片

- 点击“图片”，选择一张 JPG/JPEG、PNG 或 WebP，预览后点击“发送图片”。不支持 HEIC。
- 文件必须非空且严格小于 `6 * 1024 * 1024` 字节（6 MiB，界面简写为 6MB）。
- 服务端根据实际内容验证格式、解码图片，并限制图片不超过 6000 万像素。
- 聊天列表加载最长边不超过 480px 的 WebP 缩略图；点击后在页面内查看原图并下载。
- 原文件保持不变；缩略图根据 EXIF 方向旋转。动画 WebP 的缩略图使用首帧，原文件仍保留动画。
- 图片作为独立消息发送，不会清空正在编辑的文字；上传进度和失败原因显示在输入区。
- 图片接口沿用项目现有的登录 cookie，并检查账号是否存在。上传和下载不走公开静态目录。

## 部署和持久化

新增 `sharp` 图片处理依赖，部署时需重新安装依赖。需要同时部署更新后的服务端和前端。
反向代理应允许至少 6 MiB 的请求体（例如设置为 8 MiB）；应用仍严格拒绝大于或等于 6 MiB 的图片。

默认数据库仍是项目根目录下的 `chat.db`，图片保存在 `data/uploads/`。
两者都应保留并一起备份，不能在重新部署时删除。运行时数据不会提交到 Git。

也可以把环境变量 `CHAT_DATA_DIR` 设置为持久化磁盘上的绝对路径。
设置后，数据库位于该目录的 `chat.db`，图片位于该目录的 `uploads/`。
切换目录前应停止服务，将旧数据库及其 WAL/SHM 文件（如果存在）和图片目录一起迁移，避免出现空账号库或历史图片丢失。
启动时会为旧消息表自动补充图片字段，不会清空已有文字消息。
